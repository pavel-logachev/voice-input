# Voice Input

**Диктовка в поля ввода Windows. Поставьте курсор, зажмите `Ctrl + Shift + Space`, скажите фразу и отпустите клавиши — текст появится в поле с курсором: в мессенджере, почте, редакторе кода или браузере.** Приложение живёт в системном трее, речь распознаёт OpenAI по вашему API-ключу.

## Как пользоваться

- **Удерживать и говорить.** `Ctrl + Shift + Space`: пока клавиши зажаты, идёт запись; отпустили — текст вставлен.
- **Без удержания.** `Ctrl + Shift + K` начинает запись, повторное нажатие заканчивает. Удобно для длинных фрагментов.
- **Передумали.** `Esc` отменяет диктовку: ничего не вставится, даже если ответ распознавания придёт позже.

Над панелью задач появляется небольшой оверлей: таймер, уровень голоса и подсказка `Esc`. Цвет показывает этап — запись, распознавание, вставка, готово. Оверлей не забирает фокус и поддерживает режим высокой контрастности.

## Что предусмотрено

- В стандартные поля текст вставляется напрямую, в остальные — через буфер обмена. Буфер восстанавливается, если его содержимое за это время не менялось. Приложение запоминает окно, в котором начали диктовку. Если к моменту вставки активно другое окно, вставка отменяется. Внутри того же окна текст попадёт в поле, где курсор стоит в момент вставки.
- Запись длится до 10 минут. Когда лимит исчерпан, запись останавливается сама, а уже сказанное распознаётся и вставляется. Если микрофон отключили во время записи, диктовка завершается ошибкой устройства и ничего не вставляется.
- Сообщения об ошибках называют причину: неверный ключ, закончился баланс, нет сети, сервис недоступен.
- Если одно из сочетаний клавиш занято другой программой, приложение сообщит об этом и продолжит работать со вторым.
- Второй экземпляр приложения не запускается.

## Настройки

Двойной клик по значку в трее открывает окно настроек. В нём можно ввести, проверить или удалить API-ключ, выбрать язык речи (автоопределение, русский, английский, украинский, немецкий) и микрофон, включить автозапуск вместе с Windows. Микрофон можно сменить и из меню трея; если выбранный отключён, используется микрофон Windows по умолчанию.

## Установка

1. Откройте [последний релиз](https://github.com/pavel-logachev/voice-input/releases/latest) и скачайте `VoiceInput-Setup-1.0.0.exe`.
2. Запустите установщик. Права администратора не нужны. Установщик пока не подписан сертификатом, поэтому Windows SmartScreen может предупредить о неизвестном издателе.
3. При первом запуске откроется окно настроек. Вставьте API-ключ OpenAI (начинается с `sk-`) и нажмите «Сохранить» — ключ сразу проверится.
4. Поставьте курсор в любое поле ввода и зажмите `Ctrl + Shift + Space`.

Распознавание выполняет OpenAI, поэтому нужны интернет и собственный API-ключ; стоимость запросов списывается с вашего аккаунта OpenAI. Обновление с 0.9.x ставится поверх: ключ и настройки сохраняются. При удалении программы ключ удаляется вместе с ней.

## Приватность

- Запись существует только в памяти, пока идёт диктовка, и на диск не сохраняется.
- Звук отправляется в OpenAI только в момент диктовки. Условия обработки определяет ваш договор с OpenAI.
- Ключ хранится в `%LOCALAPPDATA%\VoiceInput\secrets`, зашифрованный Windows DPAPI для вашей учётной записи. Наружу он уходит только как заголовок авторизации запроса к OpenAI.
- История расшифровок не ведётся, телеметрии нет.
- Диагностический журнал включается только переменной `VOICE_INPUT_DIAGNOSTIC_LOG` и не содержит ни звука, ни текста.

## Как это работает

```text
Ctrl+Shift+Space нажаты
  → запоминается окно, где стоит курсор
  → запись WASAPI в память (моно, 16 кГц)
Ctrl+Shift+Space отпущены
  → расшифровка через OpenAI (модель gpt-transcribe, ваш API-ключ)
  → вставка в исходное окно: напрямую или через защищённую вставку из буфера
```

Приложение написано на .NET 10 и WPF. Подробности о процессах, потоках и обработке отказов — в [архитектуре](docs/ARCHITECTURE.md).

## Запуск из исходников

Нужны Windows 10/11 x64 и .NET 10 SDK.

```bash
dotnet run --project src/VoiceInput.App -c Release
```

В сборке из исходников есть необязательный рабочий процесс локального распознавания `VoiceInput.Asr.Worker` на модели GigaAM. Когда он лежит рядом с приложением, в настройках появляется выбор «На этом компьютере». При первом включении он загружает около 200 МБ — runtime и модель с проверкой SHA-256, — а дальше работает офлайн. В установщик 1.0 локальный движок не входит.

Переменные для тестов и параллельных запусков: `VOICE_INPUT_DATA_DIR` (папка настроек и ключа), `VOICE_INPUT_INSTANCE_NAME` (имя защиты от второго экземпляра), `VOICE_INPUT_DIAGNOSTIC_LOG`.

## Проверка

```bash
dotnet build VoiceInput.sln -c Release
dotnet test VoiceInput.sln -c Release --no-build
```

Тесты покрывают рабочий процесс диктовки, отмену и гонки, запись звука на фиктивном устройстве, клиент OpenAI и проверку ключа на подставном сервере, хранение ключа и настроек, автозапуск, горячие клавиши, вставку текста и внешний вид окон. CI собирает решение и прогоняет тесты на Windows при каждом push и pull request в `main`.

Настоящие окна приложения можно отрисовать в PNG без записи речи — так сделаны картинки в этом README:

```bash
dotnet run --project tests/VoiceInput.UiPreview -c Release -- preview
```

## Ограничения

- Установщику нужны интернет и ключ OpenAI; офлайн-режима в нём нет.
- Сочетания клавиш фиксированы.
- В программы, запущенные от имени администратора, вставить текст из обычного процесса нельзя — Windows это блокирует.
- Нет автообновления и подписи кода.
