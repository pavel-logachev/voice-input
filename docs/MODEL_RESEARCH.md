# Локальные ASR-модели для Voice Input

**Дата среза:** 2026-07-26  
**Цель:** выбрать open-source модель для локальной русской диктовки на Windows.  
**Ниже WER:** лучше. Значения из разных таблиц нельзя механически сравнивать, если различаются датасеты и нормализация.

## Короткий вывод

Да, модель Сбера существует и сейчас выглядит лучшей исходной точкой. Это **GigaAM-v3** от команды GigaChat/Salute (`salute-developers`, веса `ai-sage`).

Для первого работающего варианта рекомендую:

> **GigaAM-v3-e2e-rnnt, GGUF Q4_K_M, runtime `transcribe.cpp`, CPU backend по умолчанию.**

Почему именно эта комбинация:

- модель специализирована на русской речи;
- сразу выдаёт регистр, пунктуацию и нормализованные числа;
- MIT-лицензия у модели и runtime;
- Q4-файл занимает **175 MB**;
- в стороннем GGUF-бенчмарке квантизация почти не меняет FLEURS RU WER: **5.35% F32 → 5.36% Q4_K_M**;
- `transcribe.cpp` имеет C API, CPU/Vulkan backends и документированную Windows-сборку;
- на текущем ПК Ryzen 9 9950X и около 96 GB RAM, поэтому CPU inference должен быть практичным; Vulkan на обнаруженной AMD Radeon Graphics стоит измерить, но не назначать основным без теста.

Главный компромисс: опубликованный GGUF-вариант **не streaming** и ограничен коротким фрагментом примерно до 25 секунд. В текущем MVP после отпускания клавиши запись в памяти режется по самым тихим окнам на сегменты до 20 секунд, worker распознаёт их последовательно, а приложение вставляет собранный текст. Online VAD и параллельная обработка закрытых сегментов остаются следующей оптимизацией задержки.

## 2. Практические варианты

### Вариант A — GigaAM-v3 E2E RNNT / GGUF Q4_K_M

**Рекомендация для MVP.**

| Свойство | Значение |
|---|---|
| Назначение | Русская речь, готовый читаемый текст |
| Архитектура | Conformer + RNN-T, 220–240M параметров |
| Вывод | Регистр, пунктуация, нормализация |
| Размер | 175 MB в Q4_K_M; 431 MB F16 |
| FLEURS RU WER в `transcribe.cpp` | 5.35 F32; **5.36 Q4** |
| Опубликованная скорость | Ryzen 4750U: около 8× realtime CPU / 22× Vulkan; M4 Max: 25× CPU / 88× Metal |
| Streaming | Нет |
| Ограничение опубликованного short-form runtime | До 25 секунд на сегмент |
| Лицензия | MIT |

Сильная сторона — модель уже делает то, что нужно диктовке, без второго нейросетевого прохода. Q4 почти не теряет качество относительно F32.

### Вариант B — GigaAM-v3 E2E CTC / GGUF Q4_K_M

**Обязательный challenger в нашем тесте.**

| Свойство | Значение |
|---|---|
| Размер | 174 MB Q4_K_M |
| FLEURS RU WER | 5.50 F32; 5.57 Q4 |
| Опубликованная скорость на Ryzen 4750U | около 9× CPU / 30× Vulkan |
| Вывод | Регистр и пунктуация |
| Streaming | Нет |
| Лицензия | MIT |

CTC немного быстрее и проще, RNNT немного точнее в опубликованном FLEURS-тесте. На Ryzen 9 9950X разница в задержке может оказаться несущественной, поэтому сравним их на реальной диктовке.

### Вариант C — GigaAM-v3 RNNT без E2E

**Вариант на случай, если абсолютная точность слов окажется важнее готового оформления.**

| Свойство | Значение |
|---|---|
| Средний официальный WER | **8.3%** против 11.2% у E2E RNNT |
| Размер GGUF Q4 | 175 MB |
| Вывод | Нижний регистр, без пунктуации |
| FLEURS RU WER в GGUF harness | 8.12% Q4 |

Для приложения придётся добавлять отдельную локальную модель пунктуации/нормализации. Это увеличит сложность, задержку и количество способов испортить исходную формулировку. Поэтому не основной кандидат.

### Вариант D — GigaAM Multilingual Large CTC 600M

**Accuracy challenger, но не первый runtime.** Свежая модель 2026 года, обученная на 2 млн часов для 70+ языков.

| Русский набор | 220M | 600M | Whisper large-v3 |
|---|---:|---:|---:|
| Common Voice | 7.1 | **5.1** | 9.1 |
| FLEURS | 4.4 | **3.0** | 3.1 |
| Internal in-the-wild | 7.6 | **6.0** | 10.1 |

Проблемы для нашего MVP:

- официальный FP32 checkpoint около **2.23 GiB**;
- charwise CTC не даёт готового «красивого» текста на уровне E2E-v3;
- линия совсем свежая, Windows/GGUF-интеграция менее зрелая;
- английский у неё заметно слабее Whisper.

Имеет смысл вернуться к ней, если GigaAM-v3 будет ошибаться на нашей лексике или понадобятся казахский, кыргызский и узбекский.

### Вариант E — Russian Whisper large-v3-turbo fine-tune

Лучший запасной кандидат для русско-английского code-switching и сформированного текста: `coriollon/whisper-large-v3-turbo-russian`.

| Свойство | Значение |
|---|---|
| Aggregate WER автора на 6 RU-наборах | **8.93%** против 13.25% vanilla turbo |
| Пунктуация/регистр | Да; punctuation macro F1 0.41, case F1 0.83 |
| CTranslate2 int8+fp16 | около 782 MB |
| Лицензия | Apache 2.0 |

Это не прямое сравнение с таблицей GigaAM: здесь другой sampling и другой evaluation harness. Сама карточка модели прямо отмечает, что GigaAM лучше по raw Russian WER. Whisper остаётся полезным challenger благодаря mixed RU/EN, зрелому `faster-whisper` и устойчивости к разным доменам, но он тяжелее и как autoregressive seq2seq-модель подвержен повторам и галлюцинациям.

### Вариант F — Vosk RU 0.42

Имеет настоящее streaming API с partial results, но качество ниже современных GigaAM-вариантов.

| Модель | Размер | Опубликованный WER |
|---|---:|---|
| `vosk-model-ru-0.42` | 1.8 GB | Golos Crowd 4.4; OpenSTT audiobooks 11.1; YouTube 19.5; calls 36.0 |
| `vosk-model-small-ru-0.22` | 45 MB | Golos Crowd 11.79; audiobooks 22.71; YouTube 31.97 |

Vosk стоит держать только как технический baseline или fallback для крайне слабых устройств. На текущем ПК экономия ресурсов не компенсирует разницу качества.

## 3. Выбор runtime

### Основной: `transcribe.cpp`

- C/C++17, GGUF, MIT;
- публичный C API для P/Invoke или отдельного worker;
- CPU, Vulkan, CUDA и Metal backends;
- документированная Windows/MSVC-сборка;
- сторонние GigaAM-порты проверены против авторского Python runtime и имеют воспроизводимый WER harness;
- Q4/GGUF резко уменьшает размер без заметной потери качества.

Для стабильности приложения предлагается не грузить native runtime прямо в WPF-процесс, а держать **долгоживущий Local ASR Worker** и общаться с ним через named pipe. Тогда ошибка native backend не уронит tray/hotkey и worker можно перезапустить без потери системной оболочки.

### Проверка на целевом ПК

2026-07-26 комбинация `transcribe.cpp 0.1.3 + GigaAM-v3 E2E RNNT Q4_K_M` была реально запущена на Ryzen 9 9950X. Тестовый файл содержал 3.888 секунды синтетической русской речи: «Это проверка локального распознавания русской речи».

| Backend | Загрузка модели | Прогретый decode | Скорость |
|---|---:|---:|---:|
| **CPU** | 0.165 с | 0.206 с | **18.87× realtime** |
| AMD Radeon Vulkan | 0.132 с | 0.317 с | 12.25× realtime |

Оба backend выдали фразу без единой ошибки. Полный production workflow через отдельный worker и named pipe — fixture recorder → сегментация → GigaAM → insertion sink — завершился за **239 мс**. Поэтому в MVP зафиксирован CPU backend; Vulkan остаётся опциональным экспериментом.

### Резервный путь: ONNX Runtime

Есть MIT-конверсия `istupakov/gigaam-v3-onnx` и официальный export GigaAM в ONNX. ONNX удобен для C#, DirectML и стандартного deployment, но готовый GGUF-путь сейчас лучше документирован по размеру, WER и CPU/Vulkan throughput. ONNX оставляем вторым spike, если `transcribe.cpp` C API окажется неудобным или нестабильным.

## 4. Влияние на UX и архитектуру

Поскольку GigaAM-v3 E2E не является настоящей streaming-моделью, текущий MVP работает так:

1. overlay сразу показывает, что микрофон пишет, но не обещает ненадёжный partial transcript;
2. после отпускания hotkey mono float32 PCM остаётся в памяти;
3. длинная запись режется на фрагменты до 20 секунд по самым тихим окнам;
4. отдельный worker последовательно распознаёт фрагменты;
5. тексты соединяются и только затем передаются в insertion path;
6. никакие промежуточные куски не вставляются в чужое приложение самопроизвольно.

Следующая latency-оптимизация — закрывать сегменты по VAD ещё во время записи и отправлять их worker заранее, не меняя модель и контракт финальной вставки.

## 5. Что осталось для финального model bake-off

GigaAM-v3 E2E RNNT Q4 уже подтверждён как рабочий baseline. Для окончательного продуктового выбора нужно прогнать на личном голосовом корпусе:

1. GigaAM-v3 E2E RNNT Q4;
2. GigaAM-v3 E2E CTC Q4;
3. Russian Whisper large-v3-turbo CTranslate2 int8+fp16.

Опционально добавим raw GigaAM RNNT и Vosk как контрольные точки.

### Корпус

- короткие фразы интерфейсной диктовки;
- естественные сообщения по 10–30 секунд;
- русско-английские термины, названия продуктов и код;
- числа, даты, валюты, URL и аббревиатуры;
- тихая речь, фон и микрофон на расстоянии;
- паузы, самокоррекции и незаконченные предложения;
- несколько минут тишины/шума для проверки галлюцинаций.

### Метрики

- normalized WER и CER;
- punctuation/capitalization F1;
- ошибки в именах, числах и mixed RU/EN;
- hallucination rate на тишине;
- cold load, warm latency и end-of-speech → final;
- peak RAM и размер поставки;
- CPU против прогретого Vulkan на AMD;
- доля фраз, которые человек вынужден исправить вручную.

Продуктовый победитель — не обязательно модель с минимальным академическим WER. Для диктовки важнее суммарное число ручных исправлений и задержка после отпускания клавиши.

## 7. Уровень уверенности

- **Высокий:** GigaAM-v3 — правильное семейство для первого прототипа русской локальной диктовки.
- **Средне-высокий:** E2E RNNT Q4 — лучший первый вариант по совокупности качества, оформления и размера.
- **Высокий:** CPU быстрее Vulkan на текущей AMD iGPU — это подтверждено прогретым on-device тестом.
- **Низкий без собственного корпуса:** какая модель лучше на личной манере речи, англоязычных терминах и продуктовых названиях.
